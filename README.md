# Anime News Bot

Telegram-бот для автопостинга аниме-новостей в канал/ветку обсуждения.

## Возможности

- Сбор новостей с 14 источников (RSS + HTML парсинг)
- Перевод на русский с защитой названий (Google Translate + AniList API)
- Дедупликация, фильтры по свежести и наличию картинок
- Одна новость на разных языках — один пост. Анонс, пришедший из русских
  каналов, английских сайтов и итальянского канала («Необъятный океан»,
  «Grand Blue», «Grand Blue Dreaming»), склеивается по тайтлу: бот сверяет
  названия с базой Shikimori (бесплатно, без ключа, с кешем на диске) и
  склеивает новости с тем же тайтлом, номером сезона или серии и типом
  события — анонс, трейлер, серия, песня, перерыв. Работает и без модели,
  и между циклами. Выключается `FEATURE_WORK_IDENTITY=false`.
- Официальные русские названия тайтлов: тайтл, узнанный по Shikimori, в посте
  называется так, как его знают русские зрители, — «Необъятный океан» (Grand
  Blue), а не одно английское название. У всех постов тайтла один и тот же
  хэштег (#НеобъятныйОкеан), по нему в чате находятся все его новости. Без
  модели название меняет сам бот, с моделью — модель по подсказке. Выключатель —
  в «Настройки → 🤖 Модель».
- Рубрика «Серии на сегодня»: раз в день (`EPISODES_DIGEST_TIME`, по умолчанию
  10:00) бот публикует расписание серий из календаря Shikimori — время показа
  в Японии по часовому поясу админа, русское название, номер серии, финалы и
  отдельным списком премьеры. У премьер Shikimori знает только дату, поэтому
  время для них не пишется. Публикуется туда же, куда новости, и только при
  включённой авторассылке. Выключена, пока её не включат в «Настройки →
  📝 Посты».
- Источник «Shikimori» — раздел «Новости» Shikimori: русские новости только про
  аниме и мангу (анонсы, трейлеры, даты премьер), с картинками в полном размере
  и роликами. Бесплатный API без ключа, один запрос за цикл. Спойлеры из текста
  не публикуются. Та же новость из других источников склеивается с ней по
  тайтлу. Адрес меняется переменной `SHIKIMORI_NEWS_URL`: Shikimori уже
  переезжал с домена на домен.
- Blacklist стоп-слов (реклама/товарка)
- Отсев не-новостей по заголовку: подборки «10 лучших», тесты, рецензии,
  объяснялки, годовщины и календари именинников, скидки, фан-контент,
  серии дубляжей на чужих языках (в том числе японские «レビュー» и «特集»).
  У телеграм-каналов жанр видно ещё и по их собственным рубрикам в конце
  поста («#арт», «#календарь», «#реклама»). Решение принимается на сборе,
  поэтому такой материал не занимает ни очередь, ни вызов модели.
- Отсев чужих тем без модели: у лент общей тематики (Collider, /Film,
  Variety, Polygon, ComingSoon, Filmix и телеграм-канал «Гиковский Вестник»)
  новость идёт в канал, только если в заголовке или первых строках видно
  аниме или мангу.
- Непереведённый пост в канал не уходит: если модели нет, а переводчик не
  ответил (Google отвечает серверам 429 часами), пост откладывается до
  следующего цикла, как при недоступной модели.
  Включается там, где разбора модели нет; выключатель — в «Настройки →
  Модель и перевод», состояние видно в `/llm`.
- Режим отправки в ветку обсуждения (всё пачкой) или в канал (по одному)
- Догрузка полного текста статей со страниц
- Пачка новостей за один запрос к языковой модели: бесплатные пулы
  не выдерживают «одна новость — один вызов» (`LLM_BATCH_SIZE`)
- Метрики, логирование, retry-логика
- [Справочник переменных окружения](docs/env-reference.md) собирается из кода:
  разойтись с ним не может, инвариант следит. Свой набор переменных на живом
  боте проверяет `/doctor`, локальный детектор медиа — `/mediaping`.
- [Где взять бесплатный ключ для модели](docs/llm-providers.md) — сравнение
  бесплатных тарифов и что именно задать в переменных.
- `/llmclean` разбирает настройки модели по живым ответам провайдеров и
  говорит, что оставить, что стереть и что заменить. Слот, чей ключ отвергли,
  бот пропускает до смены ключа, а не долбит каждый цикл.
- `news_stories.py` — логика повторов новостей без состояния: одно ли это
  событие (токены, номера сезонов, тип события, аниме или манга, ядро
  названия, имя тайтла на любом языке). Первый модуль, вынесенный из `anime_news_bot.py`; бота он не
  импортирует и проверяется без токена, сети и диска.
- `post_text.py` — текст поста без модели: целые предложения, многоточие
  как обрыв, а не конец мысли, рубрики и баннеры телеграм-постов вместо
  заголовка. Второй модуль из монолита, тоже без состояния.
- `llm_protocol.py` — что бот говорит модели и как проверяет её ответ:
  промпты, пресеты провайдеров, разбор JSON, новые цифры и даты против
  источника. Сеть, ключи, лимиты и состояние отказов остаются в боте.
- `/envfile` показывает файл `.env` рядом с кодом и убирает из него строку
  (`/envfile убрать LLM_BASE_URL`). Нужен потому, что файл заполняет только
  то, чего в панели хостинга НЕТ: удаление из панели не убирает значение, а
  передаёт ход файлу, и через панель это не чинится в принципе. Значения
  ключей команда не показывает; строка комментируется, а не стирается.
  Только владельцу.
- [Локальная модерация чата](docs/chat-moderation.md): правила без LLM,
  проверка фото, GIF, стикеров и видео на наготу, учёт варнов и мутов.
- Независимые модели и бюджеты новостей и чата; мгновенная эскалация
  нарушений и обновление уведомлений вместо спама от модерации.
- Очистка статей от повторов и рекомендаций, сохранение коротких фактов,
  корректная обработка ссылок с UTM и изображений с отложенной загрузкой.

## Качество новостей и трейлеры (20 сентября 2026)

Редакционный промпт (с 23 сентября — `editorial-v5-2026-09-23`: официальные
русские названия тайтлов по подсказке Shikimori) различает анонсы, трейлеры,
слухи, новости о касте и интервью. Главный факт идёт в заголовок; детали
дополняют его. Модель получает указание сохранять даты, имена и атрибуцию,
убирать шутки вместо новости, подписи CMS и ненужные сюжетные спойлеры.
Это редакционные указания, а не гарантия фактологической проверки каждого факта.

Парсер Telegram сохраняет предложения и названия внутри ссылок/жирного текста,
реальные абзацы и пометку «Слух». Длинный исходный заголовок не обрезается до
передачи редактору. Переписывание с потерянной неопределённостью, незакрытым
названием или заголовком-обрывком отклоняется; остаётся исходный текст с обычной
обработкой. Эти проверки работают и для ответов из пакетного кеша. Причина
попадает в `_editorial_rejection` и метрику `anime_bot_editorial_rejected_total`.

Поиск видео одинаков для RSS и статьи: поддерживаются `video/source`, ленивые
iframe, YouTube No-Cookie, lite-youtube и JSON-LD VideoObject. Японские пометки
PV/тизера запускают поиск ещё до перевода. Профили X/Twitter и YouTube-каналы
больше не считаются роликами. Telegram-источники также проверяются на ссылки
на внешнее видео в собственном тексте сообщения. Найденный ролик проходит
существующие ограничения размера/длительности и отправку через yt-dlp/Bot API.

Если видео не удалось прикрепить, модератор видит предупреждение в превью,
а при отсутствии ссылки на ролик — ссылку на статью. Предупреждение не входит
в текст для канала. Закрытые, удалённые и недоступные хостингу ролики по-прежнему
могут остаться без видео; наличие одной картинки не подтверждает доставку трейлера.
Для проверки конкретного сбоя используйте `/videocheck` и `/logs`.

После обновления перезапустите бот. Новые правила применяются к новым постам;
уже опубликованные сообщения не редактируются. Для проверки нового промпта
смотрите `/llm`; если `LLM_PROMPT_VERSION` задан вручную, обновите его метку.

## Отказы модели и доставка

При временном отказе настроенной LLM новость остаётся в очереди. По умолчанию
бот откладывает её до трёх раз с интервалом 300 секунд; затем допускает обычный
перевод DeepL/Google. Настройки: `LLM_DEFER_MAX_ATTEMPTS` и
`LLM_DEFER_RETRY_SEC`. Отсрочка и счётчик сохраняются на диске, исходный срок
годности новости сохраняется, попытки отправки в Telegram не расходуются.

Переключение провайдера после ошибки сети, 5xx, 429 или отклонённого ключа
может обработать текущую новость в том же вызове. Повторы обработки, включая
снятие неподдерживаемых параметров, учитываются в дневной квоте и бюджете
токенов. Дополнительные параметры не могут заменить модель, сообщения или
лимит ответа и включить потоковый режим.

При 429 бот также пробует запасные модели на том же ключе, если ошибка
не относится к общей квоте аккаунта. Явный отказ до генерации освобождает
резерв токенов для следующего маршрута; сетевые ошибки и 5xx сохраняют
осторожную оценку расхода. Текст успешного ответа не считается ошибкой
провайдера, даже если в самой новости упоминаются ошибки моделей.

Редакторский промпт требует брать факты и контекст только из источника.
Проверка месяцев учитывает русские падежи и границы слов, а отклонение нового
текста удаляет старую версию из результата. Лимит ответа на пачку рассчитывается
по фактическому числу новостей. [Промпт для следующего аудита](docs/maintenance-prompt.md).

Для недоверенных RSS, статей и медиа соединение закрепляется за проверенными
публичными IP, каждый редирект проверяется заново. Системные HTTP-прокси для
этих запросов не используются; явный прокси отклоняется. Опциональный
`REDDIT_PROXY` в запросах к заданным адресам Reddit продолжает работать.

Если Telegram подтвердил доставку альбома, но отдельное сообщение модерации
не отправилось, пост сохраняется для ручной проверки без повторной отправки
альбома. Ошибка `BadRequest` до доставки разрешает штатную запасную отправку
изображения байтами.

## Запуск

### Переменные окружения

Обязательная:
- `BOT_TOKEN` — токен бота от @BotFather

Опциональные (есть значения по умолчанию):
- `CHANNEL_ID` — ID/username канала
- `ADMIN_ID` — Telegram ID администратора
- `DISCUSSION_CHAT_ID` — ID группы обсуждения
- `DISCUSSION_THREAD_ID` — ID темы (ветки)
- `DATA_DIR` — папка для хранения данных (для постоянного хранилища на хостинге)

### Установка и запуск

```
pip install -r requirements.txt
cp .env.example .env      # локально: впишите свои значения
python anime_news_bot.py
```

На хостинге `.env` не нужен — переменные задаются в панели.

### Версии зависимостей

`requirements.txt` — проверенный набор точных версий: новое развёртывание
ставит ровно его, а не «самые свежие на сегодня». Обновлять — отдельным PR:
поднять версию, дождаться зелёного CI. Исключение — `yt-dlp` (и то, что
приносят его `[default,deno]`): YouTube регулярно ломает старые версии.

Файл **самодостаточный** — никаких `-c`/`-r` на соседние файлы. Bothost
сначала копирует в образ один `requirements.txt` и ставит его, а код — потом;
строка `-c constraints.txt` валила сборку целиком, и не деплоилась ни одна
версия. `tests/test_requirements.py` следит и за этим, и за тем, чтобы
закреплено было всё, что тянут зависимости.

Бот ставится и на Python 3.10: хостинг может выбрать его, даже если в
`runtime.txt` указан 3.11. Для numpy и onnxruntime в `requirements.txt` по две
строки с условием `python_version`. CI проверяет: тесты на 3.11 и 3.10 и сборку
в чистых `python:3.11-slim` / `python:3.10-slim` «как на хостинге»
(`tools/hosting_smoke.py`: NudeNet, rlottie, ffmpeg, deno, импорт бота и запуск
до опроса Telegram на пустом томе данных с фальшивым токеном).

Что реально запустилось — во второй и третьей строках лога:
`Python: …` и `Окружение: Python · PTB · yt-dlp · onnxruntime · numpy · ffmpeg · deno`.

### Видео и история публикаций

- Ролики с YouTube и других хостингов качаются в отдельном процессе с общим
  сроком `VIDEO_DOWNLOAD_TIMEOUT_SEC` (300 с, вместе с ожиданием очереди) и не
  больше `VIDEO_DOWNLOAD_CONCURRENCY` (2) сразу. По сроку процесс убивается
  вместе с ffmpeg, недокачанное удаляется, пост уходит без видео.
- ffmpeg приезжает пакетом `imageio-ffmpeg` (в образе хостинга системного нет):
  YouTube, Bilibili и Niconico отдают 720p+ только раздельными дорожками, и без
  склейки ролик был в 360p или не скачивался вовсе. Формат — сначала H.264 +
  AAC до 1080p в пределах ~38 МБ (Telegram играет такие прямо в ленте), потом
  ступени ниже. `yt-dlp[default,deno]` приносит решатель JS-проверок YouTube и
  движок deno для него.
- В Telegram ролик уходит с шириной, высотой, длительностью и превью — иначе
  он показывался квадратом с чёрными полями и без длительности. Размеры берутся
  из ffprobe, а без него — из `ffmpeg -i` или из ответа yt-dlp; ролики из
  Telegram-каналов (байтами) измеряются так же.
- С серверов хостинга YouTube часто требует подтверждения «не бот» (PO-токен)
  и тогда отдаёт только 360p или ничего; это ограничение YouTube для
  дата-центров, бесплатно его не обойти. Обложкой такого поста становится
  заставка ролика `maxresdefault` (1280×720), если своих картинок у новости нет.

### Качество фото

Сверено с каналом: 6% фото бота были меньше 700 px (у админов — 1%). Причины и
что сделано:

- Ролик из Telegram-канала не доехал (длиннее 5 минут или больше 48 МБ) — в
  пост шло превью из ленты 320×180. Теперь ffmpeg достаёт кадр 1280×720 из
  первых 8 МБ самого ролика (у роликов Telegram оглавление в начале файла),
  пропуская чёрное вступление. Только хосты Telegram и только mp4.
- og:image-миниатюры (ANN `thumbnails/crop600x315`) заменяются оригиналом;
  превью YouTube — на `maxresdefault`, картинки X — на `name=large`.
- Догадка об адресе оригинала не всегда верна. Если «оригинал» не открылся,
  берётся исходная ссылка, а не пропадает картинка. Картинка, которая не
  скачалась вовсе, больше не обгоняет настоящую: раньше без данных её оценка
  (35) была выше, чем у мелкой живой, и битая ссылка роняла альбом.
- Telegram в веб-ленте отдаёт фото не больше 800 px — крупнее из открытой
  ленты канала не получить.
- Рядом с историей публикаций лежит проверенная копия `sent_links.json.lastgood`
  (обновляется не чаще раза в час). Если основной файл повреждён, бот
  поднимает копию сам и пишет об этом. Если копии нет, автопубликация встаёт на
  паузу: с пустой историей бот выложил бы заново уже вышедшие новости. Снять
  паузу — вернуть файл из бэкапа и перезапустить бота или `/historyok`
  (продолжить без истории, возможны повторы).

Один ролик YouTube с разных сайтов выходит один раз: id ролика сверяется с уже
опубликованными, как отпечаток картинки (другое событие в заголовке — «трейлер»
и «дата премьеры» со старым трейлером внутри — повтором не считается).

### Вид и язык постов

Сверено с постами живых админов канала (527 постов: у админов медиана ~90
символов, жирный заголовок у половины, эмодзи в начале; реакций на их посты
в 5 раз больше, чем на сплошной текст бота):

- пост — эмодзи по типу события (👀 слух, 🎬 трейлер, 🔥 анонс, 📺 релиз,
  📚 манга, 🎮 игры…), **жирный заголовок**, пустая строка, одна-две фразы;
  `POST_STYLE=plain` возвращает прежний вид;
- названия тайтлов — официальные русские из Shikimori для всех тайтлов
  новости, не только первого («Провожающая в последний путь Фрирен», а не
  «葬送のフリーレン» или «Sousou no Frieren»); латинский оригинал до 30
  символов — в скобках при первом упоминании;
- японские иероглифы и кана в канал не выходят: такой пост откладывается и
  переписывается заново; имена людей — по-русски (японские — по Поливанову);
- заголовок без «!» и меток «[Интервью]», тело — до двух коротких абзацев;
  пересказ вида «В источнике TG: … упомянута сцена» отклоняется.

### Сигналы тревоги

Раз в 10 минут сторож проверяет признаки поломки и пишет владельцу один раз
(повтор — не чаще `OPS_ALERT_REPEAT_HOURS`, 6 ч, пока проблема не пройдёт):

- **очередь стоит** — первый пост ждёт дольше `OPS_QUEUE_STALE_HOURS` (6 ч), а
  публикаций нет два интервала подряд; длинная, но движущаяся очередь сигнала
  не даёт;
- **диск не пишет** — `OPS_WRITE_FAILURES` (3) сбоя записи за 15 минут;
- **растут неизвестные отправки** — за сутки прибавилось `OPS_UNCERTAIN_GROWTH`
  (3) публикаций, которые Telegram не подтвердил;
- **медиа в чате без проверки** — за час `OPS_UNCHECKED_MEDIA_PER_HOUR` (15)
  непроверенных картинок и гифок.

Порог 0 выключает сигнал. Сторож тишины (8 ч без публикаций) работает как раньше.

### Нагрузка на цикл событий

Всё, что держит бота «замороженным» для всех, измерено и сокращено:

- JSON пишется быстрым C-кодировщиком и по разделам (пик памяти — самый
  крупный раздел); отступы только у файлов до 64 КБ.
- Хранилище модерации больше не копируется целиком на каждую запись и при
  откате: копируются только разделы, которые меняет действие. На файле 7 МБ
  предупреждение — 248 → 103 мс, санкция из трёх записей — 755 → 286 мс.
- Статистика источников, буфер повторов и счётчики сбора пишутся одной
  записью за цикл, а не после каждого источника и каждой истории.
- Кластеризация историй: всё про новую новость считается один раз, строки
  реестра без шанса на совпадение отсекаются точным фильтром (тесты сверяют
  решения с фильтром и без). 60 новостей на полном реестре — 148 → 34 мс.
- Отпечаток картинки для дедупа считается в потоке (65 мс на 2400×1350).
- Кеш AniList ограничен 5000 записями, под замком, пишется не чаще раза в
  минуту; история публикаций хранит 500 записей (дальше не читается).
- yt-dlp загружается лениво: ролики качает отдельный процесс.

## Команды бота

Полный список по разделам — `/help` в личке с ботом (`/help модерация` — один
раздел). Справка собирается из `HELP_SECTIONS`, и тест не пропустит команду,
которой в ней нет.

- `/start` — меню
- `/news` — свежие новости в личку
- `/preview` — превью постов
- `/start_auto`, `/stop_auto` — управление авторассылкой
- `/status` — статус
- `/stats` — метрики
- `/logs` — последние строки лога
- `/posts [N]` — последние N опубликованных постов файлом: исходный заголовок,
  источник, ссылка и текст, который ушёл в канал. Для разбора качества постов;
  данных участников чата в файле нет
- `/historyok` — продолжить автопубликацию после потери истории публикаций
  (только владелец)
- `/blacklist` — список стоп-слов
- `/chatinfo` — ID чата и темы
- `/settings` — настройки
