# Промпт для следующего аудита

Проанализируй и доработай anime-news-bot, уделяя приоритет надёжности LLM,
качеству аниме-новостей и экономии запросов. Работай от актуальной main в
отдельной ветке, сохраняя пользовательские изменения.

1. Прочитай инструкции репозитория и проверь состояние Git. Уточни реальные
   симптомы по доступным логам, не выводя токены, ключи и содержимое .env.
2. Сначала проверь LLM: выбор профиля, квоты запросов и токенов, 429/5xx,
   переключение моделей, таймауты, JSON, пакетную обработку и кеш. Затем
   проверь связанные пути публикации и откладывания новостей.
3. Исправляй воспроизводимые ошибки небольшими изменениями. На каждую ошибку
   добавь регрессионный тест, который падает до исправления. Избегай полной
   переработки архитектуры и повторного чтения больших файлов.
4. Сохрани независимость моделей новостей и модерации. Данные статьи и чата
   не должны изменять инструкции LLM. Новость должна опираться на источник;
   модель не должна дописывать факты из памяти.
5. Уменьшай лишние запросы и объём промпта с сохранением нужных фактов.
   Проверяй повторы и резервирование бюджета тестовыми HTTP-ответами.
   Для проверки качества генерации используй реальные вызовы только если
   пользователь разрешил расход API-квоты и предоставил рабочую настройку.
6. Выполни затронутые тесты, затем проверки CI и общий набор один раз.
   Повторяй только проверки, затронутые новыми изменениями или ошибками.
   Перед пересборкой BUILD_MANIFEST.json добавь новые файлы в Git.
7. Подготовь краткий отчёт: причина каждой ошибки, исправление, результаты
   проверок, измеренная экономия и что нельзя подтвердить без живых логов.
   Чётко различай локальное исправление, PR и обновление запущенного бота.

Экономь лимиты: ограничивай область поиска и вывод инструментов, используй
имеющееся тестовое окружение, делегируй только независимые короткие задачи.
