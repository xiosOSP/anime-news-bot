# Промпт для следующего аудита

Проанализируй и доработай anime-news-bot: надёжность развёртывания, качество
постов (текст, фото, видео), интерес новостей, модерация, экономия ресурсов.
Работай от актуальной main в отдельной ветке, сохраняя пользовательские
изменения.

## Сначала — факты о хостинге (Bothost, документация: bothost.ru/llms-full.txt)

- Образ собирается автоматически: `COPY requirements.txt` →
  `pip install --no-cache-dir -r requirements.txt` → код. `requirements.txt`
  обязан быть самодостаточным: никаких `-c`/`-r` на соседние файлы (из-за
  `-c constraints.txt` однажды не деплоилась ни одна версия).
- Python берётся из образа хостинга и может не совпадать с `runtime.txt`
  (бывал 3.10). Код и версии пакетов должны работать на 3.10–3.13.
- В образе нет ffmpeg, deno и прочего системного: всё нужное — только pip
  (`imageio-ffmpeg`, `yt-dlp[default,deno]`).
- `/app` монтируется с кодом из Git, `/app/data` — постоянный том (`DATA_DIR`).
- Память: бесплатный тариф 256 МБ, базовый 1 ГБ, Pro 2 ГБ. Вылет по памяти —
  «Killed», код 137, без traceback.
- Автообновление по push — только на платных тарифах; иначе «Обновить из Git».
  Ошибки установки — в «Логах сборки», падения бота — в «Логах работы».
- CI повторяет сборку хостинга: задача `hosting-image` (чистые
  `python:3.11-slim` и `python:3.10-slim`, `tools/hosting_smoke.py`: тяжёлые
  модули делают настоящую работу, бот доходит до опроса Telegram на пустом
  томе данных).

## Порядок работы

1. Прочитай инструкции репозитория и проверь состояние Git. Уточни реальные
   симптомы по доступным логам, не выводя токены, ключи и содержимое .env.
   Владельца можно попросить строки лога (без токенов), но не `/backup`.
2. Если бот не запускается — сначала деплой: соберись «как хостинг» (только
   requirements.txt в пустой папке, затем `tools/hosting_smoke.py`), проверь
   3.10 и 3.11.
3. Качество постов сверяй с живым каналом: `t.me/s/<канал>` отдаёт посты с
   подписями авторов (бот против админов), реакциями и картинками (до 800 px).
   Реальный текст канала и чата в репозиторий не попадает: в тестах —
   пересказанные примеры, в отчётах — пересказ.
4. Проверь LLM: выбор профиля, квоты запросов и токенов, 429/5xx, таймауты,
   JSON, кеш. Новость должна опираться на источник; модель не дописывает
   факты из памяти. Модели новостей и модерации независимы.
5. Модерация: никаких автоматических банов — бан только кнопкой админа 🚫;
   муты и предупреждения бот выдаёт сам.
6. Исправляй воспроизводимые ошибки небольшими изменениями. На каждую ошибку —
   регрессионный тест, который падает до исправления; каждый новый тест
   ловит мутацию (прогон мутаций с таймаутом, исходники после него сверить).
7. Выполни затронутые тесты, затем CI целиком один раз: pyflakes, ruff F821,
   pytest (BOT_TOKEN, DATA_DIR) на 3.10 и 3.11, `tools/build_manifest.py
   --check` (после `git add -A`), `tools/check_invariants.py`,
   `tools/env_reference.py --check`.
8. Отчёт владельцу по-русски и просто: причина → исправление → проверка →
   что сделать в панели. Различай локальное исправление, PR и обновление
   запущенного бота.

Только бесплатные инструменты и сервисы. Комментарии в коде — по-русски и
объясняют «почему». Экономь лимиты: ограничивай область поиска и вывод
инструментов, делегируй только независимые короткие задачи.
